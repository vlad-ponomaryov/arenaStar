# План этапа 2 — Офлайн-прототип боя

Цель этапа (GDD §3.2): управление, атаки, суперудары, 6 бойцов на примитивах, 1 карта, режим «Жёлуди», боты.
Без сети, аккаунтов и магазина. Порядок — GDD §12.3 (пункты 1–10).
**Готово, когда:** матч 3×3 с ботами идёт от начала до конца на телефоне среднего уровня при стабильных 30+ FPS;
10 тестеров сыграли по 5+ матчей и большинство хотят ещё (оба пункта — **человеком**).

Общие правила, окружение, рабочий цикл — `CLAUDE.md`. Архитектура и причины — `Docs/Decisions.md`.
Числа, которых нет в GDD (скорости снарядов, заряд ульты, радиусы бойцов и т. п.), агент выбирает сам, кладёт в сидер
и записывает в Decisions.md с пометкой `PROTO` (D-013).

## S2.1 — Ядро симуляции и данные бойцов

**Цель.** Чистая детерминированная симуляция: ввод, состояние, тик 30 Гц, движение, заряды атаки, регенерация,
снапшот; SO-конфиги бойцов и правил боя с конвертацией в Core-Defs и сидером.

**Файлы.**
- `Core/Math/Vec2.cs`, `Core/Math/MathUtil.cs` (Clamp, Lerp, угол↔вектор, поворот, `Approximately`).
- `Core/Random/DeterministicRng.cs` (struct, xorshift128+ или PCG32 на `ulong`; `NextUInt`, `NextFloat01`, `Range(int,int)`, `Range(float,float)`).
- `Core/Input/PlayerInput.cs`, `Core/Input/InputButtons.cs` — см. D-006.
- `Core/Sim/SimLimits.cs` (дополнить), `Core/Sim/SimTime.cs` (`SecondsToTicks` с округлением, `Dt`).
- `Core/State/FighterState.cs`, `Core/State/MatchGlobals.cs`, `Core/State/MatchState.cs` (`CopyFrom`, `ContentEquals`).
- `Core/Defs/FighterDef.cs`, `Core/Defs/CombatRules.cs`, `Core/Defs/MatchDefs.cs`, `Core/Defs/MatchSetup.cs`,
  `Core/Defs/PlayerSlotSetup.cs`, `Core/Defs/ArenaBounds.cs` (временный прямоугольник до S2.5).
- `Core/Sim/MatchSimulation.cs`, `Core/Sim/Systems/MovementSystem.cs`, `ChargeSystem.cs`, `RegenSystem.cs`.
- `Core/Sim/Events/SimEvent.cs`, `SimEventType.cs`, `SimEventBuffer.cs` (кольцо/массив фикс. ёмкости, `Clear` в начале тика).
- `Data/FighterConfig.cs`, `Data/CombatRulesConfig.cs`, `Data/GameDatabase.cs` (списки конфигов, карта по умолчанию — позже),
  `Data/Conversion/ConfigConverter.cs` (→ `MatchDefs`), `Data/SpeedClass.cs` (Slow/Normal/Fast).
- `Assets/_Project/Editor/Data/DataSeeder.cs` (`Arena.Editor.Data.DataSeeder.SeedAll`).
- Ассеты: `Assets/_Project/Data/Combat/CombatRules.asset`, `Assets/_Project/Data/Fighters/{Pix,Bruno,Chomp,Kora,Nova,Vex}.asset`,
  `Assets/_Project/Data/GameDatabase.asset`.

**Что сделать.**
1. `MatchSimulation(MatchDefs defs, MatchSetup setup)` выделяет `MatchState` один раз; `Tick(PlayerInput[] inputs)` (индекс = слот бойца):
   порядок систем фиксирован и записан в комментарии класса: ввод/кнопки → движение → заряды → регенерация → `Tick++`.
2. Движение: `velocity = Normalize(move, max 1) * speed`, мгновенно (без инерции), позиция ограничена `ArenaBounds`
   с учётом радиуса; `Facing` — по прицелу, иначе по движению. Скорость — из `CombatRules` по `SpeedClass` (2,2/2,5/2,8).
3. Заряды: `MaxCharges = 3` (из правил), восстановление по одному за `AttackRechargeTicks` бойца; хелпер `TryConsumeCharge`.
4. Регенерация: после `RegenDelay` (3 с) без атак и урона — +12 % макс. здоровья в секунду (накопитель дробной части в состоянии).
   Поле `LastCombatTick` обновляется при атаке/уроне (атаки появятся в S2.3).
5. Уровень бойца: `+6 %` HP/урона за уровень выше 1 (`CombatRules.LevelBonusPerLevel`), применяется при конвертации/спавне.
6. SO: значения в секундах/клетках; конвертер переводит в тики/`int`. Сидер создаёт/перезаписывает ассеты (D-010):
   все 6 бойцов с базовыми параметрами из GDD §6 (HP, скорость, дальность атаки, время заряда); способности — позже.
   Идентификаторы бойцов: `pix`, `bruno`, `chomp`, `kora`, `nova`, `vex`; ключи имён `fighter.pix.name` и т. д.

**EditMode-тесты** (`Core/…`, `Data/…`): `Vec2Tests`; `DeterministicRngTests` (одинаковый seed → одинаковая последовательность,
границы `Range`); `MovementTests` (путь за 1 с = скорость ±1 %, диагональ нормализована, упор в границы, три класса скорости);
`ChargeTests` (трата, восстановление по одному, не больше 3); `RegenTests` (нет регена до 3 с, затем 12 %/с ±1 %, сброс при уроне);
`SnapshotTests` (`CopyFrom` → N тиков в обеих копиях с одинаковыми входами → `ContentEquals`); `DeterminismTests`
(две симуляции, один seed и входы → идентичны после 900 тиков); `AllocationTests` (после 30 тиков прогрева 300 тиков —
`GC.GetAllocatedBytesForCurrentThread()` не растёт); `ConfigConverterTests` (Pix из ассета: HP 3400, Normal 2,5,
заряд 1,4 с = 42 тика); `DataSeederTests` (двойной запуск не плодит ассеты, в `GameDatabase` 6 бойцов).

**Критерий готовности.** compile 0, тесты зелёные, ассеты в git; коммит(ы) `S2.1: …`.

## S2.3 — Снаряды и зоны поражения с пулами; урон, смерть, возрождение (12.3/3)

**Цель.** Атака тратит заряд и порождает снаряды (Пикс: 4 капли очередью) или мгновенную зону (Бруно: конус 90°);
урон, смерть, возрождение через 3 с. **Капсулы двигаются и стреляют.**

**Файлы.**

  `Core/State/AreaState.cs` (позиция, радиус, `ActivateTick`, `ExpireTick`, команда, владелец, AbilityRef — для отложенных зон).
- `Core/Defs/AbilityDef.cs`, `Core/Defs/DeliveryKind.cs` (пока `Projectile`, `MeleeCone`), `Core/Defs/EffectDef.cs`,
  `Core/Defs/EffectKind.cs` (пока `Damage`), `Core/Defs/TargetFilter.cs` — структура сразу как в D-011, чтобы S2.4 только расширял.
- `Core/Sim/Systems/AttackSystem.cs` (фронт кнопки + заряд → выстрел; очередь: `BurstShotsLeft`, `NextBurstTick` в `FighterState`),
  `TargetingSystem.cs` (автоприцел — ближайший видимый враг в радиусе атаки, D-007), `ProjectileSystem.cs` (движение с проверкой
  отрезок–окружность, без повторного попадания по `HitMask`), `AreaSystem.cs`, `DamageSystem.cs` (единая точка урона/лечения,
  события, смерть, накопление `UltCharge` — поле есть, логика в S2.4), `RespawnSystem.cs`.
- `Core/State/FighterStats.cs` (урон, победы, смерти — для MVP в S2.7).
- `Data/AbilityConfig.cs`, `Data/EffectConfig.cs` (сериализуемые классы внутри `FighterConfig`), сидер: атаки Пикса и Бруно.
- `Gameplay/View/ProjectileViewPool.cs` (пул по слотам массива снарядов, предсоздание `MaxProjectiles` не нужно — прогрев 64,
  рост только при старте матча), `Gameplay/View/HealthBarView.cs` (полоска HP и зарядов над бойцом — простые квады, без текста).
- `ViewAssetBuilder`: префаб `Projectile` (сфера), материал `Projectile`.

**Что сделать.** Урон по своим отсутствует. Смерть: `Alive=false`, `RespawnTick = Tick + RespawnTicks`, событие; возрождение в точке
спавна команды с полным HP и зарядами. Переполнение пула снарядов — выстрел пропускается, счётчик `DroppedProjectiles` в
глобальном состоянии (без исключений и аллокаций). Числа `PROTO`: скорость капли, интервал очереди, радиус снаряда.

**EditMode-тесты.** Снаряд пролетает `speed*dt` за тик и исчезает на дальности; попадает во врага, не в союзника; урон уменьшает HP;
смерть при HP ≤ 0, возрождение через 90 тиков с полным HP в точке спавна; атака без зарядов не стреляет; очередь из 4 капель с
интервалом; автоприцел выбирает ближайшего врага в радиусе и игнорирует дальних; ручной прицел — по направлению; конус Бруно бьёт
цель внутри 90°/2,5 и не бьёт снаружи; переполнение пула не бросает исключение; `AllocationTests` со стрельбой — 0 байт.

**Критерий готовности.** compile 0, тесты зелёные; вручную (утром): стрельба по манекенам, смерть и возрождение. Коммит `S2.3: …`.

при смерти теряется половина, расход — фронт кнопки. Трюк: 3 применения, откат 5 с, направление — движение (иначе взгляд).

рывок 3 клетки по движению; талант +10 % скорости при заряженной ульте) и Бруно (ульта «Таран» — рывок 6, 1000, отброс 2, оглушение
0,5 с, `BreaksWalls`; трюк «Каска» — −40 % урона 2 с; талант +15 % урона при HP < 40 %).

**EditMode-тесты.** Заряд ульты от урона; нельзя применить незаряженную; после применения 0; смерть — половина; трюк: 3 раза и откат

## Проверка утром (заполняет агент S2.13)

1. Открыть проект в Unity Editor, сцена Boot → Play: меню, выбор бойца, матч, WASD/мышь, итоги.
2. Подключить телефон (отладка по USB), `Tools/build-android.ps1 -Install`.
3. Профилирование: `Tools/build-android.ps1 -Development -Install`, Unity Profiler → подключиться к устройству, матч 2,5 мин с ботами,
   смотреть FPS, GC Alloc на кадр, draw calls (< 100), треугольники (< 150 тыс.).
4. Пройти `Docs/Questions.md`.
