# Карта «Снежная долина» (новогодняя) — дизайн уровня

Решение пользователя 19.10 (D-136): **первая карта — новогодняя «Снежная долина»**: ёлка посередине, под ней подарки,
снеговики; всё играбельно и сбалансировано под наш геймплей. Визуальная основа — концепт
`Art/Source/Flow/2026-10-19_locations/07_snow_valley.png` (понравился пользователю: снег, тропы, снежные крепости, ели, ледяной
пруд, снеговики), праздничный слой — из `11_stump_newyear.png` и `Docs/Location-Hub.md` §3.1 (Новый год: ёлка с золотыми,
белыми, оранжевыми шарами, подарки кремовые с золотой/лиловой лентой, снеговик вместо бочки, сугроб вместо камня).

Документ — только дизайн. Код, данные и ассеты не менялись; внедрение — отдельным шагом (сидер `DataSeeder`, см. §6).

## 0. Что поддерживает симуляция сейчас (проверено по коду)

| Символ (`MapConverter`) | `TileType` | Движение | Снаряды | Примечание |
| --- | --- | --- | --- | --- |
| `.` | `Floor` | да | да | |
| `#` | `Wall` | нет | **блокирует** | |
| `%` | `BreakableWall` | нет | блокирует | ломают способности с `BreaksWalls`: ульта Бруно (таран) и ульта Чомпа (бревно) → пол |
| `"` | `Bush` | да | да | прячет бойца; враг видит ближе 2 клеток (`BushRevealDistance`) или 1 с после атаки (D-024) |
| `~` | `Water` | нет | **пролетают** | |
| `$` | `BerryBox` | нет | блокирует | только в «Последнем звере» имеет прочность и даёт ягоды (`BoxSystem`); в других режимах — просто стена |
| `A` / `B` | пол + спавн команды 0 / 1 | | | k-й спавн команды — k-му бойцу |
| `S` | пол + общий спавн | | | режимы «каждый сам за себя» |
| `H` | **пол** + дупло | | | дупло «Желудей»; конвертер всегда делает клетку `H` полом |

- Формат: `MapConfig.Rows` (строки сверху вниз), строка 0 в `MapDef` — нижний край (команда 0, D-009). Лимит `SimLimits.MaxMapCells = 2048`.
- Текущие карты: «Поляна» `acorns_glade` 21×31 (пишется нижняя половина + средняя строка, верх — `MirrorBottomHalf`),
  «Чаща» `royale_thicket` 45×45 (пишется четверть 23×23, `MirrorQuarter`). Командные карты обязаны быть центрально-
  симметричны (`MapSymmetry`: клетка (c, r) = (W−1−c, H−1−r), k-й спавн A ↔ k-й спавн B, дупло — центральная клетка).
- «Жёлуди»: жёлудь каждые 6 с, золотой раз в 60 с, разброс от центра дупла радиусом 1,5 клетки (`AcornSpawnScatter`),
  8 попыток найти непроходимую-не-блок клетку, иначе — **центр дупла**. Боты без видимых желудей идут в центр дупла.
- Дальности атак (сидер): Пикс 8, Нова 10, Кора 7, Чомп (навесом) 7, Бруно 2,5 (конус), Векс 1,8 (конус). Скорость 2,2 / 2,5 / 2,8 клетки/с.
- Радиус тела 0,45–0,55 → **Бруно (0,55) не пролезает в проход шириной 1 клетку**. Поэтому на карте нет проходов уже 2 клеток.

**Проверено скриптом (BFS по клеткам):** все 566 проходимых клеток связаны; нет тупиков (клетка с ≥3 закрытыми сторонами);

спавна до кольца вокруг ёлки — 14 клеток (≈5,6 с при 2,5 кл/с), до ближайшего вражеского спавна — 30–32 клетки.
Самый длинный прострел по вертикали — 17 клеток по краевым колонкам 0–1 / 19–20, через центр (колонки 9–11) — 3–4.

### 1.1. Ёлка и дупло — главное решение

- Ёлка — **непроходимое укрытие, блокирует выстрелы** (тип `Wall`, не ломается ультами). Форма «плюс» 5 клеток: визуально
  круглая ель ~3 клетки, коллизия совпадает с силуэтом нижних лап (углы 3×3 — пол, туда можно прижаться). Через ёлку не
  простреливается ни одна из 4 линий к центру, но по диагоналям центр открыт — в центре нельзя «сидеть за одной стеной».
- В «Желудях» жёлуди **выкатываются из-под ёлки** (ёлка = дупло этой карты). Сейчас это **не поддерживается** без
  мелкой правки кода (клетка `H` всегда пол, разброс при неудаче кладёт жёлудь в центр, бот идёт в центр дупла) — см.
  предложение П1 (§1.3). Пока П1 не сделано — **вариант А0**: центр `.....H.....` пол, вместо 5-клеточной ёлки — низкая
  «ёлочка-дупло» без коллизии (как сейчас дуб: стоять на клетке можно), вокруг те же 4 подарка. Разница в сетке только в 5
  клетках:

```
А0 (работает сейчас):            П1 (цель):
r16  ..~~.............."".        r16  ..~~......#......."".
r15  ...#......H......#...        r15  ...#.....#T#.....#...
r14  .""..............~~..        r14  ."".......#......~~..
```
(в А0 строки r14/r16 — те же, что в основной сетке, но без `#` в колонке 10: `.""..............~~..`).

### 1.3. Предложение П1 (не обязательное) — «дупло на непроходимой клетке»

Нужно, чтобы ёлка была и укрытием, и источником желудей. Новый `TileType` **не нужен**:
1. `MapConverter`: символ `T` = `Wall` + `Hollow` (как `H`, только клетка — стена).
2. `PickupSystem.ScatterPoint`: если все попытки неудачны — ближайшая проходимая клетка к центру (а не сам центр, который
   внутри стены); `AcornSpawnScatter` для этой карты — 2,2 (данные режима/карты; при 1,5 вокруг «плюса» ~⅔ попыток падают в
   ствол, с 2,2 — ~⅓, отказ 8 попыток ≈ 0,01 %). Лучше — поле `HollowScatterRadius` в `MapConfig`, чтобы «Поляна» не менялась.
3. `Perception` (боты): цель «дупло» — ближайшая проходимая клетка к `Hollow`, а не его центр.
4. Тесты: жёлудь никогда не появляется в блок-клетке; бот доходит до дупла-ёлки; симметрия карты с `T`.
Оценка: ~40 строк + 3–4 EditMode-теста. Альтернатива без кода — вариант А0 (низкая ёлочка без коллизии).

## 2. Разбор геймплея («Жёлуди»)

**Три линии** (для команды 0, снизу вверх):
- **Левый фланг (кол. 0–5) — «ледяной»:** свой пруд (2–3, 8–9), снеговики (4, 11–12) и (3, 15), свой ельник у середины
  (1–2, 13–14), дальше чужой пруд (2–3, 16–17) и чужой глубокий ельник (1–3, 21–22). Пруды не держат выстрелы — фланг для
  стрелков (Пикс 8, Нова 10): стреляют через лёд, не подпуская ближних. Самый длинный прострел (17 клеток по колонкам 0–1)
  — длиннее любой атаки, поэтому снайперской «линии смерти» нет.
- **Центр (кол. 6–14):** база → горка подарков (9–11, 6) → снежная крепость `###` (9–11, 10) → ельник (6–7, 12–13) и подарок
  (8, 13) / подарок (12, 13) → ёлка. Ступенчатые укрытия через каждые 3–4 ряда, прямого прострела вдоль центра нет (≤4 клетки).
- **Правый фланг (кол. 15–20) — «лесной»:** свой ельник-засада (17–19, 8–9) и снеговик (18, 7) у базы, крепость «Г»
  (15–16, 11–12), свой пруд у середины (17–18, 13–14), напротив — чужой ельник (18–19, 16–17). Фланг для ближних
  (Бруно, Векс): из ельника 2×3 до выхода на центр — 5–6 клеток, конус Бруно 2,5 бьёт из куста почти в упор.
- Каждая команда получает одно и то же: «ледяной» фланг слева, «лесной» справа (центральная симметрия) — стороны равны.

**Центр и контроль.** Ёлка «плюс» в центре + 4 подарка по диагоналям в 2 клетках + ельники (6–7, 12–13) и (13–14, 17–18).
Жёлуди падают в кольце 1,5–2,2 клетки вокруг ёлки — подобрать можно с любой из 4 сторон, ёлка закрывает от выстрела с
противоположной стороны: схватил жёлудь — обошёл ёлку — ушёл. Ельник каждой команды стоит **слева от центра в своей
половине**, в 3,5 клетки от ёлки: дальше радиуса раскрытия (2 клетки), т.е. засада у центра есть, но подбор жёлудя
выводит из куста. Подарки у ёлки ломаются ультами Бруно/Чомпа → к концу матча центр открывается (позднее давление сильнее).

**Дистанции.** Ширина центра от крепости до крепости (9–11, 10) ↔ (9–11, 20) — 9 рядов: стрелки 8–10 держат её, ближние
прорываются через фланговые ельники. Поперёк поля на средней линии — 21 клетка, снеговики (3, 15) и (17, 15) делят её
на три отрезка ≤7. От крепости до ёлки — 4 ряда: «пятачок» для ближнего боя у центра.

**Время до контакта.** До ёлки 14 клеток ≈ 5,6 с (быстрые 5,0 с, Кора 6,4 с); первый жёлудь — на 6-й секунде, т.е. обе
команды подходят как раз к первому жёлудю. Стрелки видят противника на ~3–4 с. С возрождения (3 с) до центра — тоже ~5,6 с:
проигравший размен не отрезан от центра надолго, но и не возвращается мгновенно.

**Нет мёртвых зон и тупиков:** проверено скриптом (§1). Угловые ельники у баз (1–2, 1) / (18–19, 1) — укрытие при
отступлении, не «кемп» у чужого спавна: до вражеского спавна от них 4–5 клеток, видно в радиусе раскрытия.

**Сторона против стороны:** при игре за «верх» карта для игрока поворачивается на 180° (база внизу экрана) — раскладка та же
клетка в клетку.

## 4. Визуальный список элементов (3D)

Палитра снега — не чисто белый: пол `≈#E8EEF2` с тёплыми тенями, тропы — утоптанный снег с песочно-коричневым (как в 07).

| Элемент | Клетки | Модель | Читаемость / контраст | Слабые телефоны |
| --- | --- | --- | --- | --- |
| **Ёлка** | плюс 5 | ель-конус 3 яруса, шары **золотые, белые, оранжевые, лиловые** (без красных и синих — цвета команд), звезда-снежинка, гирлянда тёплых лампочек — цвет запечён в текстуру | тёмная хвоя на снегу 6,5:1; нижний ярус ≤0,8 клетки высотой у ствола, верх — прозрачнеет при бойце за ней (или ограничить высоту ~2,5 клетки, чтобы не закрывать север) | 1 меш ~1,5k tris, без света от гирлянд |
| **Подарки** | 1 | кубик с бантом, бок темнее верха; цвета **мятный/золотой/лиловый** с белой или золотой лентой | кремовый на снегу — 1,06:1, **не читается** → только насыщенные коробки с тёмным низом | 300 tris, общий атлас, 3 перекраски |
| **Снеговик** | 1 | 2–3 шара, ведро/шапка, шарф **зелёный или лиловый** (не оранжевый/красный — путается с врагами) | белое на белом → контур тени + тёмная шапка, тёплая AO-«лужица» под ним | 400 tris |
| **Снежная крепость** | 2–3 | снежные кирпичи (как в 07) на тёмном деревянном/каменном цоколе | снег на снегу 1,1:1 → цоколь и контактная тень обязательны (D-130) | instancing |
| **Сугроб у края** | 2 | пологий вал с голубоватой тенью | то же | 200 tris |
| **Ельник-куст** | 1 | 2–3 ёлочки в 0,9 клетки, тёмная хвоя, снег на макушках | **белый/голубоватый куст-сугроб не годится: 1,1:1 к снегу**; тёмно-зелёный — 6,5:1 к снегу и 2:1 к кольцам команд (кольца видны) | общий меш, GPU instancing |
| **Ледяной пруд** | 2×2 | лёд бирюзово-серый **с деревянным бортиком** (как круглый пруд D-132), трещинки в текстуре | лёд к снегу 1,2:1 → читается только бортиком и тенью; лёд не насыщенно-синий, чтобы не путать с синим кольцом своих | плоский меш, без отражений |
| **Рамка** (вне поля) | — | заснеженные ели, 2 бревенчатых домика, дрова, санки, гирлянды на столбиках забора | вне клеток, не влияет на бой | LOD/импостеры для ельника |
| Снегопад | — | редкие хлопья | выключен на слабых | частицы ≤50 |

**Дальтонизм и цвета команд.** Свои — синее кольцо `#3385FF` (3,0:1 к снегу), враги — красное `#F2382E` (3,3:1),
